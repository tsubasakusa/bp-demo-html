#696 文本語料 API 說明（前端串接用）

更新日期：2026-11-22，對應分支 feature/696-corpus-research（e99529ba）。內容依程式碼整理，路由定義見 backend/routes/{backstage,frontstage}/{corpus,feedback_corpus}.php，主要邏輯在 backend/app/Module/Corpus/。進度與待辦見 696-status.md。

1. 共通規則

1.1 回應格式

所有 API（下載類成功時除外）都回 JSON，HTTP 狀態碼一律是 200，以 success 與 code 判斷結果：

{ "success": true, "code": 200, "s_message": "", "payload": { } }
{ "success": false, "code": 400, "s_message": "請填寫原因" }
  • 失敗時沒有 payload；code 可能是 400、401、403、404、409、500。
  • 驗證錯誤的 s_message 是中文訊息，可直接顯示（本文件列出的錯誤訊息都是 s_message 的實際內容）。
  • 找不到資料時 code: 404，s_message 為中文，例如「找不到文本資料集」、「找不到檔案」、「找不到意見回饋」。
  • 權限不足：code: 403，s_message: "權限不足"；後台未登入：code: 401，s_message: "Not Login"。
  • 例外：後台請求完全沒帶 token 時回 HTTP 401（s_message: "TOKEN_NOT_FOUND"），axios 會走 error 分支。
  • 前台未登入呼叫需登入的 API：HTTP 200、code: 401、s_message: "Unauthorized"。
  • 409 代表資料已被其他操作更新，前端應重新載入（見 1.4）。

1.2 驗證與身分

使用端 API 位址 身分
後台 backstage API，/api/v1/... Authorization: Bearer <jToken>；.download、.export 結尾的 GET 也可用 jToken cookie，因此可直接用瀏覽器開啟
前台 frontstage API，/api/v1/... 公開：corpus.list、corpus.info、corpus.term.list、corpus.resource.download；其餘都要新北卡會員登入（session）

1.3 角色與資料範圍

角色 role_id 可管理的文本資料集
系統管理者 siteadmin 41886952-d56e-4572-afff-14378c75d741 全部
機關資訊業務 depadmin 39f45e00-109a-4120-9d73-ae886ffe9df1 所屬一級機關之下
資料提供者 provider 1610f100-53b8-4c13-b30a-5a46aa0b3526 只有自己擁有的

審核權限另外限制：

  • 機關審核（狀態 a03/b03/d03）：只有被指派且同機關的 depadmin 可以同意或退回。
  • 系統審核（狀態 a05/b05/d05）：只有 siteadmin 可以同意或退回。siteadmin 可以看到機關審核中的資料，但不能審核。

選單權限：siteadmin、depadmin 有編輯、審核、移轉、意見回饋四項；provider 只有編輯與意見回饋。API 本身不檢查選單權限，只檢查上面的範圍。

1.4 版本與並行（重要）

文本資料集每次儲存都會產生新的版本：

  • 編輯類 API（corpus.revise、corpus.resource.*、corpus.term.set）都要帶目前的 revision_id，成功後回傳新的 revision_id，下一次呼叫必須改用新值。
  • 帶舊的 revision_id 會回 code: 409，訊息為「資料已更新，請重新載入後再編輯」（審核類為「資料已更新，請重新載入」）。
  • 修改已上架資料時，前台持續顯示上架版本，要等第二關審核通過才切換。

1.5 日期格式

  • 時間欄位為 Y-m-d H:i:s；collection_start、collection_end 一律是 Y-m-d（corpus.info 與 corpus.review.info 相同）。

2. 狀態碼

狀態 意義 狀態 意義
a01 [新上架]草稿 c05 已上架
a02 [新上架]退回 d01 [下架]草稿
a03 [新上架]機關審核中 d02 [下架]退回
a05 [新上架]系統管理者審核中 d03 [下架]機關審核中
b01 [修改]草稿 d05 [下架]系統管理者審核中
b02 [修改]退回 e05 已下架（終態）
b03 [修改]機關審核中 deleted 取消新草稿後的內部狀態，列表不會出現
b05 [修改]系統管理者審核中

c02、c04、e02（系統退回）與 c01、c03、e01 在文本語料流程中不會出現。

允許的操作（CorpusWorkflow.php）：

操作 狀態變化
儲存（revise、檔案異動、分類設定） a01/a02→a01；c05/b01/b02→b01。下架草稿與下架退回（d01/d02）不可儲存，只能送出下架或取消
submit_new 送審新上架 a01/a02 → a03
submit_edit 送審修改 c05/b01/b02 → b03
submit_unpublish 申請下架 c05/d01/d02 → d03
agency_approve 機關同意 a03→a05；b03→b05；d03→d05
site_approve 系統同意 a05→c05（上架）；b05→c05（換成新版本）；d05→e05（下架）
reject 退回 a03/a05→a02；b03/b05→b02；d03/d05→d02
withdraw 抽回（只限機關審核中） a03→a01；b03→b01；d03→d01
cancel 取消 a01/a02→deleted；b01/b02/d01/d02→c05（回到上架版本）

不允許的操作會回「目前狀態無法編輯」或「目前狀態無法執行此操作」。

第二關通過後：新上架與下架各產生一筆公告事件，修改不產生公告。

3. 分類與檔案

3.1 分類（kind）

kind 名稱 預設選項
type 文本資料類型 政府出版品、政府計畫/報告、研究報告、政策與施政文件、活動與宣傳文本、臺灣在地文化、語言資源/詞彙、教育與學習資源、互動性溝通語料
domain 應用領域 農業發展、健康醫療、能源管理、金融經濟、交通運輸、綠色永續、觀光旅遊、災害防救、文化藝術、公共行政
language 語系 正體中文、臺語、客語、原住民族語、英文、日文、韓文
  • 每種 kind 可多選；另可加一筆自訂「其他」，送 { "kind": "domain", "custom_value": "育兒" }（不帶 term_id，1～500 字）。
  • 自訂值的顯示：後台回傳原始 custom_value；前台列表顯示「其他」；前台詳目顯示「其他 [育兒]」。
  • 送審時 type、domain、language 都至少要選一項。
  • corpus.term.list 依名稱排序，不是依預設順序。

3.2 檔案

  • 上傳欄位名稱 upload，一次一個檔案（multipart/form-data）。
  • 格式：PDF、ODT、JSON、XML、TXT、CSV（副檔名不分大小寫），系統也會檢查檔案內容是否符合副檔名。
  • 單檔上限 100 MB；每個資料集 1～20 個檔案（送審時檢查至少 1 個）。
  • 檔名不可含 /、\、控制字元，最多 500 字。

4. 後台 API

4.1 GET corpus.list 文本資料集列表

依角色範圍列出（provider 只看到自己的）。

參數 說明
q 比對名稱
status 逗號分隔的狀態碼
exclude_status 逗號分隔，要排除的狀態碼
ou 逗號分隔的機關代碼，受角色範圍限制
uid 擁有者（provider 會被強制為本人）
page_num、page_limit 預設 1、10；page_limit 最大 100

回傳：{ total, records }，依狀態變更時間由新到舊。每筆：id、owner_uid、unit_id、unit_full_name（「機關/科室」）、status、working_revision_id、title、description、egov_account、first_published_at、last_published_at、status_changed_at。

4.2 GET corpus.info 單筆詳目

參數：id。權限：可管理此資料集的角色。

回傳：

  • 資料集欄位：id、owner_uid、unit_id、status、working_revision_id、published_revision_id、first_published_at、last_published_at、status_changed_at、created、changed
  • working_revision：工作版本（編輯中的內容），可能為 null
  • published_revision：上架版本，從未上架時為 null

Revision 物件：

欄位 說明
id、corpus_id 版本與資料集 id
title、description 名稱（≤500 字）、描述
license_code、license_permanent、license_expiry_year 授權方式、是否永久、截止年度
egov_account eGov 帳號
provider_uid、provider_unit_id、provider_unit_name、provider_name、provider_email 資料提供者（由系統帶入，不可編輯）
contact_name、contact_email、contact_phone 對外顯示聯絡人
collection_start、collection_end 收錄期間 Y-m-d
publication_year_start、publication_year_end 發布年份
related_url、spatial_coverage、notes 相關網址、空間範圍、備註
open_status public 全公開、ai_training 限 AI 訓練
created_by、created 建立者、建立時間
resources [{ id, original_name, file_format, mime_type, size, position }]，file_format 為大寫副檔名，size 單位 bytes
terms [{ id, kind, term_id, custom_value, created_by, position }]，自訂值的 term_id 為 null

4.3 POST corpus.add 建立草稿

權限：provider、depadmin、siteadmin，且帳號需有所屬機關。

Body（JSON），草稿階段全部選填：

欄位 型別與限制
title 字串，≤500 字，不可與其他資料集重複
description 字串
license_code 字串，≤100 字；送審時須為 SAITDL-1.0、ODC-By、CC-BY-SA、ODbL、CC-BY-NC、CC-BY-ND、CC-BY-NC-SA、CC-BY-NC-ND
license_permanent JSON 布林值或 null（字串 "true" 會被拒絕）
license_expiry_year 4 位數年份；非永久授權時送審必填
egov_account 字串，≤500 字
contact_name、contact_email、contact_phone 字串，≤500 字；未提供時預設帶入登入者資料；email 須為正確格式
collection_start、collection_end Y-m-d，結束不得早於開始
publication_year_start、publication_year_end 4 位數年份，結束不得早於開始
related_url 字串，≤2048 字
spatial_coverage、notes 字串
open_status public 或 ai_training（送審時檢查）

傳 null 或空字串代表清空該欄位。

回傳：{ id, revision_id, status: "a01" }

錯誤：「欄位格式錯誤：<欄位>」、「結束時間不得早於開始時間」、「聯絡人電子郵件格式錯誤」、「發佈結束年份不得早於開始年份」、「文本資料集名稱不得重複」。

4.4 POST corpus.revise 修改內容

Body：id、revision_id，加上 4.3 中要修改的欄位；只有傳入的欄位會被更新。

回傳：{ id, revision_id: <新版本>, status }。已上架資料修改後狀態變為 b01。

錯誤：同 4.3，另有 409（版本已變更）、「目前狀態無法編輯」。

4.5 POST corpus.resource.add / corpus.resource.replace / corpus.resource.delete 檔案異動

multipart/form-data（delete 也可送 JSON）：

欄位 add replace delete
id、revision_id 必填 必填 必填
resource_id — 必填（要被替換的檔案） 必填
upload 必填 必填 —

回傳：{ id, revision_id: <新版本>, status, resource_id }；resource_id 是新檔案的 id，delete 沒有此欄位。

錯誤：「檔案操作參數格式錯誤」、「請選擇檔案」、「檔案上傳失敗」、「每個檔案不得超過100 MB」、「檔案名稱格式錯誤」、「檔案格式不支援」、「檔案內容與格式不符」、「最多上傳20個檔案」、「找不到要操作的檔案」、409、「目前狀態無法編輯」。

4.6 GET corpus.resource.download 下載單一檔案

參數：id、resource_id、version（working 預設，或 published）。

成功時回檔案本體（application/octet-stream，檔名在 Content-Disposition 的 filename*）；失敗時回 JSON（HTTP 200），前端需判斷回傳的 Content-Type 是否為 application/json。審核頁可用 version=published 下載前次上架的檔案。

4.7 GET corpus.term.list 分類選項

回傳：{ total, records: [{ tid, name, machine_name, weight, image_url, kind }] }，只含啟用中的預設選項。

4.8 POST corpus.term.set 設定分類

整組替換，Body：

{
  "id": "...", "revision_id": "...",
  "terms": [
    { "kind": "type", "term_id": "<tid>" },
    { "kind": "domain", "term_id": "<tid>" },
    { "kind": "domain", "custom_value": "育兒" },
    { "kind": "language", "term_id": "<tid>" }
  ]
}
  • 每一項只能帶 term_id 或 custom_value 其中一個；最多 100 項，空陣列代表清空。
  • 回傳：{ id, revision_id: <新版本>, status }。
  • 錯誤：「分類參數格式錯誤」、「分類格式錯誤」、「分類選項重複或格式錯誤」、「其他選項每個類別限一項」（custom_value 為空字串時也是這個訊息）、「其他選項格式錯誤」、「分類選項不存在」、409。

4.9 POST corpus.review 送審、審核、抽回、取消

欄位 說明
id、revision_id 必填
action submit_new、submit_edit、submit_unpublish、agency_approve、site_approve、reject、withdraw、cancel
reason submit_edit、submit_unpublish、reject 必填
reviewer_uids 送審（submit_*）必填，1～100 位同機關、啟用中的機關資訊業務，不可重複

權限：同意與退回依 1.3 的審核規則；其他操作需可管理此資料集。

送審新上架與修改時會做完整檢查：

  • 「請填寫必填欄位：<欄位>」：title、description、license_code、egov_account、contact_name、contact_email、contact_phone、open_status，以及系統帶入的 provider 欄位
  • 「資料集描述不可與資料集名稱相同」、「授權方式不正確」、「開放狀態不正確」、「電子郵件格式不正確」
  • 「請選擇授權有效期間」、「請選擇授權截止年度」、「發佈年份區間不正確」（兩個年份都必填）
  • 「收錄日期格式不正確」、「結束時間不得早於開始時間」、「請上傳1至20個檔案」、「請選擇必填分類：」

其他錯誤：「審核操作參數格式錯誤」、「請填寫原因」、「請選擇審核人員」、「審核人員不得重複」、「審核人員必須為同機關的機關資訊業務」、「目前狀態無法執行此操作」、409、403。

回傳：{ id, revision_id, status }。取消新草稿時 status 為 deleted。

4.10 GET corpus.review.list 待審列表

權限：depadmin（只看到指派給自己的機關審核）、siteadmin。

參數：q（比對名稱與描述）、stage（all 預設、agency 機關審核、site 系統審核）、ou、page_num、page_limit。

回傳：{ total, records: [{ id, owner_uid, unit_id, unit_full_name, status, working_revision_id, title, description, first_published_at, status_changed_at }] }。siteadmin 用 stage=all 也會看到機關審核中的資料，但無法審核。

4.11 GET corpus.review.info 審核詳目

參數：id。權限：目前輪到自己審核才能讀取，否則 403。

回傳：id、status、revision_id、working_revision、published_revision，以及：

"review": {
  "submission_action": "submit_edit",
  "reason": "補充 2025 年資料",
  "previous_rejection": null
}

previous_rejection 是本輪之前被退回的原因。修改審核可比較 working_revision.resources 與 published_revision.resources 顯示檔案差異。

4.12 GET corpus.review.history.list 歷程

參數：id、page_num、page_limit。

回傳：{ total, records }，由新到舊。每筆：id、revision_id、from_status、status、action（create、save、submit_*、agency_approve、site_approve、reject、withdraw、cancel、transfer）、message（原因；移轉時為「來源姓名 -> 目標姓名」）、title、created、user_name、user_fullname、user_unit_full_name。

4.13 GET corpus.transfer.list 可移轉清單

權限：depadmin、siteadmin。參數：uid（來源提供者，必填）、ou（必填）、q、page_num、page_limit。只列出已上架（c05）的資料，回傳格式同 4.1。缺少參數時回「請選擇機關及資料提供者」。

4.14 POST corpus.transfer.submit 機關內移轉

欄位 說明
from_provider_uid、to_provider_uid 來源與目標提供者，不可相同
egov_account 目標機關的 Myegov 帳號（須登記在該機關）
corpus_ids 1～100 筆已上架資料集 id
  • 整批成功或整批失敗。
  • 移轉不經審核，前台立即顯示新的聯絡資訊；識別碼、首次上架時間、訂閱、回饋都保留。
  • 回傳：{ records: [{ id, revision_id }] }
  • 錯誤：「移轉參數格式錯誤」、「目標資料提供者不存在或已停用」、「Myegov 帳號不屬於目標機關」、409「資料提供者或版本已變更，請重新載入」、403（非同一一級機關、狀態非已上架等）。

4.15 GET feedback.corpus.list 意見回饋列表（後台）

權限：依角色範圍（provider 只看自己資料集的意見）。

參數 說明
q 比對意見內容
start、end Y-m-d，含結束當天
status 1 未處理、2 處理中（已暫存）、3 已結案
taxonomy 文本資料集描述有誤、文本資料集檔案內容有誤、肯定與鼓勵、其他
ou、page_num、page_limit page_limit 1～100

回傳：{ total, records: [{ id, corpus_id, title, taxonomy, content, status, unit_id, unit_full_name, created, changed }] }。

4.16 GET feedback.corpus.info 意見回饋詳目

參數：id。回傳意見內容（user_type、user_email、taxonomy、content、reply_content、status、created、changed）、資料集資訊（title、unit_full_name、member_account），以及處理人員（handler_account、handler_name、handler_role_name，未處理時為 null）。

4.17 POST feedback.corpus.review 暫存或送出回覆

Body：id、action（save 暫存、send 送出並結案）、reply_content（必填）。

  • save 後狀態為 2；send 後狀態為 3，並通知會員。
  • 已結案（狀態 3）的意見不能暫存，也不能再送出（「此意見已結案」），避免重複寄信。
  • 回傳：{ id, status, changed }
  • 參數有任何錯誤都回「請輸入回復內容」。

4.18 GET feedback.corpus.export 匯出 CSV

參數同 4.15（不分頁，匯出全部符合條件的資料）。成功時回 CSV 檔（UTF-8 含 BOM），失敗時回 JSON。

5. 前台 API

5.1 GET corpus.list 公開列表（公開）

參數 說明
q 比對名稱與描述
sort views 瀏覽次數（預設）、latest 最新上架
ou 逗號分隔的機關代碼
domain 應用領域的 tid；other 代表有自訂領域的資料
page_num、page_limit page_limit 1～100

只列出上架中的資料，內容一律取上架版本。

回傳：{ total, records: [{ id, title, description, open_status, unit_id, unit_full_name, last_published_at, view_count, formats, domains }] }

  • formats 是字串陣列，例如 ["CSV","PDF"]，沒有檔案時為 []
  • domains 是字串，以「、」連接，自訂值顯示為「其他」

5.2 GET corpus.info 公開詳目（公開）

參數：id。下架或不存在時回 404。

回傳：id、title、description、last_published_at、license_code、license_permanent、license_expiry_year、contact_name、contact_email、contact_phone、open_status、unit_full_name、subscription_count、average_rating（尚無評分時為 null）、terms: [{ kind, name }]、formats（字串陣列，與列表相同，例如 ["CSV","PDF"]）。會員登入時另有 my_rating、subscribed。

  • 不包含檔案清單、收錄期間、發布年份等欄位。
  • 每次呼叫瀏覽次數加 1。

5.3 GET corpus.resource.download 全檔 ZIP（公開）

參數：id。成功時回 ZIP 檔（corpus-<id>.zip，內含上架版本所有檔案）；失敗時回 JSON。

  • open_status 為 ai_training 時一律回 code: 403、「須經審核通過後方可取得下載連結」，因為 AI 授權申請功能尚未實作。

5.3.1 GET corpus.resource.download.check 下載前檢查（公開）

參數：id。做與 5.3 相同的檢查（上架中、全公開、檔案都存在），但不打包 ZIP、不計入下載次數。

  • 可下載時回傳 { downloadable: true }；否則回傳與 5.3 相同的錯誤。
  • 前台詳目的「下載 ZIP 檔案」按鈕先呼叫這支，成功才導向 5.3 的網址由瀏覽器直接下載（ZIP 可能很大，不經由前端記憶體）；失敗時在頁面顯示 s_message。

5.4 POST corpus.star.upsert 評分（會員）

Body：id、rating（1～5）。回傳：{ subscription_count, average_rating, my_rating, subscribed }。錯誤：「評分須為 1 至 5 顆星」。

5.5 POST corpus.subscribe、corpus.unsubscribe（會員）

Body：id。重複呼叫結果相同。回傳同 5.4。

5.6 GET corpus.term.list（公開）

同 4.7。

5.7 GET feedback.corpus.list 我的意見（會員）

參數：q、page_num、page_limit。回傳：{ total, records: [{ id, corpus_id, title, taxonomy, created, reply_status }] }，reply_status 為「已回復」或「未回復」。

5.8 GET feedback.corpus.info 我的意見詳目（會員，只能看自己的）

參數：id。回傳：id、corpus_id、title、taxonomy、content、created、reply_status、reply_content、reply_time（未回覆時兩者為 null）。

5.9 POST feedback.corpus.submit 送出意見（會員，需 reCAPTCHA）

欄位 說明
token reCAPTCHA token
corpus_id 上架中的資料集 id
user_type 應用開發、學術研究、政府機關、其他
taxonomy 文本資料集描述有誤、文本資料集檔案內容有誤、肯定與鼓勵、其他
content 意見內容，必填

回傳：{ id }。會員 email 由系統帶入。

錯誤：「No Token」、「Token validate fail」、「Token verify has error」（皆 code 401）、「請填寫紅框處必填欄位。」、「會員電子信箱無效，請至新北卡會員系統更新」、404。

6. 既有 API 的變動

  • #745 公告：前台公告等文章 API（news.* 等）的每筆資料多了 source_type，值為 "corpus" 或 "dataset"；"corpus" 時顯示「文本」標籤。
  • #746 資料集詳目：前台 dataset.info（上架版本）多了 resource_last_modified（Y-m-d H:i:s，無有效值時為空字串），定義與列表的更新時間排序相同。詳目即時計算、列表讀索引，索引延遲時兩者可能暫時不同。

7. 已知問題與注意事項

尚未處理、串接時請留意：

  1. 前台 corpus.info 每次呼叫都會累加瀏覽次數，沒有去重（與既有資料集相同；是否去重待確認）。
  2. 移轉不會檢查目標帳號的角色（規格待確認）。
  3. 錯誤處理：除「完全沒帶 token」外，一律以 success 判斷，不要依賴 HTTP 狀態碼。

已處理（2026-11-22）：找不到資料改回中文訊息；formats 列表與詳目統一為字串陣列；審核詳目的收錄期間改為 Y-m-d；前台 ZIP 下載先呼叫檢查 API；下架草稿不可編輯；後台編輯頁只在內容有變動時才儲存；已結案的意見不可再送出。

本文件依程式碼整理，回應範例尚未以實際呼叫逐一核對；串接時若發現不一致，以實際回應為準並回報更新本文件。
