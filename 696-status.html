#696 文本語料進度與待辦

更新日期：2026-11-22。本文件記錄目前完成的項目、驗證結果與待辦；需求與設計見 開發計畫，前端串接見 API 說明。

目前狀態

  • 分支 feature/696-corpus-research 已推送至遠端，最新為 e99529ba feat(corpus): 新增文本語料專區初版 (#696)；與 master（b66ce874）之間沒有落差。
  • 此分支已加入 testing 部署（32ebb89f），每次一般 push 都會部署到 testing；只想推程式不部署時加 -o ci.skip。
  • 2026-11-18 推送 e99529ba 時已觸發 testing 部署，pipeline 結果尚未確認。
  • 初版涵蓋 #744–#752：6 支 migration、後端 API、前後臺頁面、兩階段審核、多檔、移轉、意見回饋，以及公告與通知的事件處理器。

已完成的驗證

離線單元測試：cd backend && vendor/bin/phpunit tests/Proj --filter 'Corpus|ResourceLastModified|FrontMemberAuth'，157 項測試、386 個斷言全部通過。

本機整合測試（2026-11-10，空資料庫加開發用假資料，直接呼叫 API）：

項目 結果
115 支 migration 由空庫套用（含 #696 的 6 支） 通過（另需修補一支既有 migration，見下方「repo 既有問題」）
新增草稿、分類、上傳、送審、機關同意、系統同意後即時上架 通過
權限：同機關非指定審核人、跨機關、提供者自審、跳過機關審核 皆被拒絕
退回（須填原因）、抽回、重新送審、取消申請 通過

以舊 revision_id 儲存被拒（循序模擬） 通過

全公開 ZIP 下載、AI 限制資料直接呼叫下載被拒、「其他 [育兒]」 通過

意見回饋：會員送出、後臺列表與詳目、匯出 CSV、跨機關不可回覆 通過（reCAPTCHA 以開發環境開關略過）

瀏覽器（headless Chromium）實際開啟前臺列表、詳目與後臺編輯、新增、審核、移轉、意見回饋、預覽、歷程頁，無 JS 或 API 錯誤；後臺僅以系統管理者 b103 操作。

已修正：CorpusStore::termOptions() 原本寫 COLLATE "C"，dibi 會轉成字串 'C' 造成 PostgreSQL 語法錯誤，分類 API 全數失敗；已改為 COLLATE [C]。

待辦

  • 到 GitLab 確認 feature/696-corpus-research 在 testing 的 pipeline 結果。
  • 在 testing 執行 #696 的 6 支 migration；CI 不會自動執行，未執行時文本語料頁面會出錯。
  • 確認 testing 的 CI 變數（CONFIG_SYSTEM 等）已有 #696 需要的設定。
  • 通知團隊 testing 目前部署的是此分支，master 再次部署時會覆蓋。

  • migration 回滾，以及已有資料時的情境。
  • 真正同時送出的並行操作；資料庫交易或檔案儲存失敗後的回復。

本機開發環境

位置：repo 外的 ~/project/ntpc-od-696-dev/，原始碼以唯讀方式掛載進容器，不會寫入工作樹。

cd ~/project/ntpc-od-696-dev
./up.sh all        # 前臺 http://localhost:3000/corpus、後臺 http://localhost:5173
./reset-db.sh      # 重建空資料庫
  • 需要 Docker Desktop 執行中並開啟 WSL 整合；後臺第一次安裝需在 generated/backstage.npmrc 放入可讀取 RD/bp-npm 套件的 token。
  • 後臺登入頁按「取得token並登入」即以系統管理者 b103 登入；另有 dev_dep_a、dev_dep_a2、dev_prov_a（機關 A）與 dev_dep_b（機關 B）可透過 POST /api/jwt/demo/login 取得 token。
  • 流程測試腳本：e2e/flow.py、e2e/extras.py。
  • 開發環境限定的調整都在 patch-migrations.py 與 gen-config.py：修補舊 migration 與 seeder、補齊設定檔缺少的欄位、reCAPTCHA 略過開關（僅 dev／testing 生效）、API 與前臺網址設定。
